# W4A16 MoE decode kernel 优化

## 会话目标

针对 batch-one/token-one decode 优化 `E=256,N=256` W4A16 MoE，减少 routing、
alignment、两阶段 expert GEMM、activation 和 requantization 的 kernel 数量。

## 当前事实

- 配置：
  `vllm_metax/model_executor/layers/fused_moe/configs/E=256,N=256,device_name=MXC500,dtype=int4_w4a16.json`
- 核心实现：`vllm_metax/model_executor/layers/fused_moe/fused_moe.py`
- MetaX WNA16 kernel：`csrc/moe/moe_wna16.cu`
- 量化 dispatch：`vllm_metax/quant_config/moe_wna16.py`
- profiler 中五步有 430 次 `fused_moe_kernel_gptq_awq`，约 86 次/token；
- 另有 `moe_align_block_size`、top-k/routing、activation、quantization 和 copy；
- 当前主 GEMM kernel 约 `4.63 ms/token`，不含所有 helper；
- CUDA A100 比较必须使用 standard FusedMoE；upstream MegaMoE 要求 SM100。

## 基线与验证边界

- 当前 TP=4、MTP=0、100-token decode 基线为 `15.2334 tok/s`、`65.65 ms/token`，四卡利用率 `16.2–16.4%`；旧 `11.6247 tok/s`/`86 ms` 仅作历史参考。
- MTP1 的 `17.8358 tok/s` 仅作观察；出现 token divergence 时不得验收。
- 验证链固定为 kernel-validator（差分/graph gate）→ test-runner → profiler（按需归因）→ benchmark-runner（同 workload 的 E2E）。isolated MoE speedup 不等于 E2E。
- 10K prefill 的 Torch sparse MLA OOM 是独立阻断项，不能被 MoE 或 decode 提升掩盖。

## 第一任务：冻结真实运行形状

捕获 100 个 decode token 的：

- top-k expert IDs/weights 和 expert histogram；
- sorted token IDs、expert offsets、padding/alignment；
- stage1/stage2 输入输出、scale、zero point 和 packed int4 layout；
- 当前 tuned config、block shape、grid、workspace；
- 每个 helper 和 GEMM 的独立 latency。

建立可重放工具：

- `tools/debug/bench_deepseek_v4_w4a16_moe.py`
- `tools/debug/diff_deepseek_v4_w4a16_moe.py`
- `tests/model_executor/test_deepseek_v4_w4a16_moe.py`

同时复用现有 int4 MoE 测试入口：

```bash
pytest -q tests/kernels/moe/test_moe.py -k int4
```

## 优化顺序

1. 验证当前 mcoplib/Triton 分支和 tuned config 是否真正命中；记录 kernel 名。
2. 对 token-one 建立专用 routing/alignment，避免通用大 batch metadata 工作。
3. 融合 stage1 epilogue、activation 和 stage2 输入量化。
4. 评估 persistent/grouped expert kernel，复用 workspace 和 metadata。
5. 评估 stage2 output 与后续 TP reduction/residual consumer 的融合边界。
6. 只有真实 expert 分布证明有效时才缓存 routing metadata；不能假设 expert 固定。

不要在本会话修改 attention、MHC 或 collective 实现；通过 NVTX/benchmark 将收益
限定在 MoE，避免把其他阶段波动算作 MoE 提升。

## 验收指标

- W4A16 数值与当前实现满足既有量化容差，端到端 token IDs 完全一致；
- graph capture/replay 和 workspace pointer 稳定；
- MoE kernel launches 至少减少 2x；
- isolated MoE 延迟至少降低 30%；
- TP=4 100-token median/p90 有可重复收益，方差小于 3%；
- 无额外 CPU routing 同步或 per-token JIT/autotune。
